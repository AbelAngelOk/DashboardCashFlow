# Release v2.1.0 — Documentación de Producto

**Fecha**: 2026-08-04
**Tipo**: Release documental (sin cambios de código)

---

## Objetivo

Cerrar la brecha de documentación del proyecto: hasta v2.0.0 toda la documentación era **técnica** (arquitectura, modelo de datos, Server Actions, detalle por módulo). Faltaba la vista de **producto**: qué hace el sistema, con qué entidades de dominio trabaja y cómo se relacionan entre sí, en lenguaje independiente de la implementación.

## Decisiones tomadas

| Decisión | Justificación |
|----------|---------------|
| Documento único en vez de varios | El valor del documento está en mostrar las relaciones **entre** módulos; fragmentarlo lo anularía. Los módulos individuales ya tienen su doc en `/docs/modules/` |
| Numeración `10-` | Continúa la serie `00-`–`09-` de referencia transversal, en lugar de un nombre suelto |
| Distinguir Pasivo de Obligación | Son entidades distintas que conviven en la misma columna del Balance; era la ambigüedad conceptual más importante sin documentar |
| Documentar límites conocidos | Evita expectativas equivocadas sobre funcionalidad inexistente (cotizaciones automáticas, presupuestos, importación bancaria) |
| Sin referencias a archivos de código | Mantiene el documento estable ante refactors; las referencias técnicas quedan enlazadas a los docs correspondientes |
