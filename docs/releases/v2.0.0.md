# Release v2.0.0 — UX, Agrupación de Flujos y Documentación

**Fecha**: 2026-06-30
**Tipo**: MAJOR — Nueva infraestructura documental + UX overhaul + nuevas páginas de detalle

---

## Objetivo

Mejorar la experiencia de usuario general del dashboard con una sidebar colapsable, agrupación de gastos e ingresos, navegación por ícono Eye hacia páginas de detalle, y establecer la infraestructura completa de documentación técnica del proyecto.

---

## Funcionalidades incluidas

### 1. Sidebar colapsable
- Toggle mediante ícono de chevron en el AppSidebar
- Estado persistido en `localStorage` bajo la clave `cashflow:sidebar-collapsed`
- En modo colapsado: solo se muestran íconos (sin labels)
- Badge de notificaciones sigue visible en modo colapsado

### 2. Agrupación de Gastos
- Botón "Agrupar" en la página `/gastos` activa modo de selección
- Selección múltiple con checkbox por fila
- Barra de acciones sticky inferior: "Crear nuevo grupo" o "Asignar a grupo existente"
- Grupos colapsables con nombre editable inline, count de miembros y botón eliminar
- Quitar un registro de un grupo sin eliminar el registro
- Los grupos se renderizan primero, los registros sueltos después

### 3. Agrupación de Ingresos
- Misma funcionalidad que Gastos, con `groupType: "INCOME"` en la tabla `groups`

### 4. Dashboard con grupos colapsables
- Los grupos de Gastos e Ingresos aparecen en el dashboard como filas de cabecera colapsables
- Header de grupo: nombre + count de miembros + totales por moneda
- Registros dentro del grupo renderizan igual que los sueltos (edit/delete/marker/Eye)
- Registros sin grupo aparecen debajo de los grupos

### 5. Ícono Eye para Ingresos y Gastos
- Todas las filas de tipo ingreso y gasto en el Dashboard tienen ícono Eye en hover
- El ícono navega a `/ingresos/{id}` o `/gastos/{id}` respectivamente
- Activos ya tenían el ícono Eye; ahora los tres tipos son consistentes
- Obligaciones extra rows: ExternalLink reemplazado por Eye con hover-opacity

### 6. Página detalle `/gastos/[id]`
- Server Component que carga `loadGasto(id)` + `loadLinksForGasto(id)`
- Panel de información: monto, moneda, fecha, fuente (obligation/asset/libre)
- Cadena de versiones: link a versión anterior y siguiente si existen
- Panel de links Gasto↔Ingreso con los ingresos que lo financiaron
- 404 via `notFound()` para IDs inválidos

### 7. Página detalle `/ingresos/[id]`
- Mismo patrón que `/gastos/[id]` con `loadIngreso(id)` + links de gastos financiados

### 8. Infraestructura documental
- `/docs/CHANGELOG.md` — historial completo del proyecto
- `/docs/releases/*.md` — notas de cada versión
- `/docs/modules/*.md` — documentación funcional por módulo
- Cabeceras semánticas de versión en todos los documentos existentes
- Política de documentación guardada en memoria persistente

## Decisiones arquitectónicas

### Reutilización de tablas `groups`/`record_groups` para flujos
La base de datos ya tenía un modelo `Group` con `groupType: "ASSET" | "INCOME" | "EXPENSE" | "LIABILITY"`. En lugar de crear nuevas tablas, se reutilizaron los valores `INCOME` y `EXPENSE`. Esto evitó una migración y mantuvo coherencia con la tabla existente de grupos de activos.

### Grupos en dashboard como prop separada (no FinancialRecord fake)
En lugar de sintetizar `FinancialRecord` falsos de tipo grupo para el dashboard, se pasaron los grupos como prop `flowGroups?: FlowGroupWithMembers[]` a `SectionTable`. Esto evita contaminar el tipo `FinancialRecord` y mantiene el renderizado de grupos como lógica condicional dentro del componente.

### Server Components para páginas de detalle
Las páginas `/gastos/[id]` e `/ingresos/[id]` son Server Components. No necesitan interactividad en el mount inicial — toda la data se carga en servidor. Esto evita estados de carga client-side y simplifica el código.

## Riesgos

- Los grupos de flujos (gastos/ingresos) no tienen orden manual: se muestran en orden de creación (`createdAt asc`). Si se necesita reordenar en el futuro, se requeriría un campo `order` en la tabla `groups`.
- El dashboard carga los grupos con un `useEffect` separado: hay un flash breve sin grupos al cargar la página. Solución futura: moverlos a un Server Component o Context.
